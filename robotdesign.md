ADRIG canonical robot

Source of truth

Use adrig-robot-canonical-reference-v2.png as the only robot identity reference for every new ADRIG illustration.

The earlier adrig-robot-master-reference.png is an exploratory concept and is superseded by v2. Do not attach both files to a generation request because competing references will reintroduce identity drift.

The v2 reference was generated from these supplied visual roles:

Ai_Automation(2).png: primary face, body, material, and proportion reference;

LLM_Development(2).png: secondary crown, cheek, jaw, and optical-detail reference;

Workflow_Automation(2).png: mechanical-action inspiration only, not an identity reference.

The finished service screenshots must not be reused as future character references. They contain different robot designs, UI, text, and scene lighting. The canonical v2 sheet resolves those differences into one character.

Locked character properties

Agents must preserve all of the following:

feminine-neutral humanoid face and calm expression;

rounded white crown and narrow blue forehead seam;

pale electric-blue optics;

white cheek plates and blue jawline accents;

layered navy neck mechanics;

slim pearlescent-white torso and limbs;

deep-navy inner joints;

five-finger articulated hands;

identical panel seams and blue-light locations;

blank recessed chest badge for the official ADRIG SVG overlay.

Do not redesign the robot to match a service. Service meaning comes from pose, environment, system objects, and motion—not a new head, body, color, or costume.

Required generation workflow

Attach only adrig-robot-canonical-reference-v2.png as Image 1.

Describe Image 1 as the primary identity reference, not as the composition reference.

Generate one service scene per request. Do not ask for several unrelated heroes in one image.

Repeat the identity-lock paragraph in every request and edit.

Reject an output if the face, crown, body ratio, hands, chest badge, panel seams, or blue-light placement changes.

Keep typography, navigation, service labels, and UI copy outside the bitmap.

Reusable generation prompt

Use case: stylized-concept
Asset type: ADRIG <service-name> website hero illustration

Input images:
- Image 1 — CANONICAL IDENTITY REFERENCE. Reproduce the exact same ADRIG robot. Preserve its facial identity, expression, crown geometry, optics, jaw accents, body proportions, panel seams, joints, hands, feet, materials, blank chest badge, and blue-light placement.

Primary request:
Place the canonical ADRIG robot in a scene that explains <service mechanism> by showing <specific transformation or relationship>.

Scene/backdrop:
White and very light cool-grey engineered environment with restrained blueprint structure. Add only the objects required to explain the service.

Composition/framing:
Landscape website visual. The robot and mechanism occupy 75–90% of the visual area. Preserve a clean crop and sufficient responsive-safe margin. No embedded page copy.

Identity lock:
Change only pose, gaze, hand position, camera, and service-specific objects. Keep the robot from Image 1 unchanged. The chest badge remains blank for the official ADRIG SVG overlay.

Color palette:
White #FFFFFF, canvas #F7F9FC, cool grey #D9E2EE, navy #071A33, ADRIG blue #1463FF, pale blue #CFE0FF. Blue is an accent, not a full-image wash.

Lighting/mood:
Soft broad studio key from upper left, restrained cool-blue rim, delicate contact shadows, calm enterprise mood.

Constraints:
No text, letters, numbers, labels, icons, logos, navigation, dashboard copy, watermark, or signature. No second robot identity.

Avoid:
Purple, pink, orange, yellow, green, red, rainbow, aurora, dark theme, cyberpunk, aggressive expression, bulky proportions, cartoon styling, exposed wires, generic glowing brain, decorative equations, and unrelated UI cards.

Development integration

Keep this PNG in the design-source area; do not ship the model sheet to website visitors.

Export each approved production scene as AVIF with WebP fallback. Preserve its source PNG separately.

Render headings and body copy in HTML using Inter 400/500. Italic emphasis is allowed; do not bake typography into the image.

Overlay the official ADRIG logo as SVG only when the chest badge is large enough to remain crisp.

Use the raster for the cinematic base. Implement route lines, nodes, cursor response, scroll progress, and reveal motion with SVG, CSS, or Framer Motion.

Do not animate the bitmap with large scale or rotation. Prefer 1–3% parallax, 2–4px hover response, and low-amplitude head/hand movement derived from layered assets.

Provide a static final state for prefers-reduced-motion: reduce.

A meaningful image needs alt text describing the service relationship. A purely decorative image uses alt="".

Acceptance checklist

The robot is immediately recognizable as the v2 canonical character.

The service is understandable without embedded labels.

At least 90% of the image uses the ADRIG core palette.

ADRIG blue indicates active paths or states instead of decorating everything.

The official logo and all typography remain code-rendered.

The section remains understandable if animation is disabled.
